— Core Design Thesis
01 — Problem Space

Why Most AI Products
Feel Broken

Model intelligence is no longer the bottleneck. GPT-4, Claude, Gemini — they are all capable. The real failure point is upstream: how the product talks to the model, how it handles context, and how it adapts across user states and domains.

Four failure patterns recur across every category of AI product:

⚡

Inconsistent Outputs

No structured prompt system means the same user action produces wildly different results on different days. Trust collapses after 3–4 bad experiences.

🌍

Zero Domain Adaptation

A general-purpose assistant gives the same tone and depth to a medication question as to a casual recipe request. Domain context is never established.

🧩

No Context Memory

Conversations restart from zero. User history, preferences, and prior goals never inform the current response. The AI feels amnesiac and impersonal.

🛡️

Unsafe Behavior in High-Stakes Domains

Medical AI that speculates on diagnoses. Finance AI that gives confident predictions without risk disclosure. Trust-breaking moments with serious consequences.

02 — Core Framework

The AI Interaction Stack

A reusable five-layer model that defines where meaning is created, where context is managed, and where safety is enforced — before a single token is generated.

Input Layer
User Intent

Captures raw user input and classifies intent: question, command, emotional statement, or ambiguous signal. Handles voice, text, and structured form data. Responsible for initial disambiguation.

Intent: "I've been having chest pain" → classify as medical concern, high urgency signal
Context Layer
History · Goals · State

Maintains conversation history, user profile, stated goals, behavioral signals, and current session state. Feeds retrieved context into downstream layers. The AI's working memory.

Context: User is 38F, logged 3 days of low activity, asked about fatigue last week → adjust tone to concerned/supportive
Prompt Layer
System + Dynamic

Constructs the full prompt from system instructions, retrieved context, and dynamic modifiers based on user state. This is the primary design surface — the layer where AI behavior is authored.

System: "You are a wellness coach. User is showing burnout signals. Respond with empathy first, advice second."
Reasoning Layer
AI Processing

The model processes the assembled prompt. Chain-of-thought, tool use, retrieval augmentation, and safety classifiers operate here. Largely opaque — which is why the layers above must be bulletproof.

Model reasoning: symptom triage → safe information retrieval → disclaimer injection → structured response formation
Response Layer
Structured Output

Parses, validates, and formats the model's output. Applies response templates (Insight → Action → Explanation → Encouragement), injects disclaimers, and selects presentation format (chat bubble, card, list).

Output: parsed into {insight, action, explanation} → rendered as conversational card with expandable details
03 — Interaction Patterns

Six Patterns for
AI Interaction

Not every AI product should use the same interaction model. Pattern selection is a design decision that must match the use case, user state, and risk level of the domain.

Conversational

Conversational AI

Open-ended, chat-based interaction with no predefined flow. User drives the direction entirely.

When General Q&A, exploration, creative tasks
Risk Hard to keep on-topic or safe in regulated domains
UX Win Feels natural, low friction, familiar
Guided Flow

Guided Flows

AI leads the user through a structured sequence of steps. Reduces cognitive load in complex tasks.

When Onboarding, medical intake, financial planning
Risk Can feel rigid or paternalistic if overused
UX Win Completeness, safety, reduced drop-off
Proactive

Proactive AI

AI initiates interactions based on detected patterns, time, or inferred user need. Nudges before being asked.

When Habit loops, reminders, risk alerts
Risk Notification fatigue, perceived as invasive
UX Win Timely, feels like a coach not a tool
Reactive

Reactive AI

Responds only when the user explicitly asks. No assumptions, no unprompted behavior.

When Reference lookup, calculators, fact-checking
Risk Misses moments where intervention would help
UX Win Predictable, user-controlled, trustworthy
Adaptive

Adaptive AI

Learns from user behavior over time. Changes tone, depth, and suggestions based on observed patterns.

When Long-term coaching, education, fitness
Risk Overfitting to past behavior, echo chambers
UX Win Feels genuinely personal over time
Ambient

Ambient AI

Operates silently in the background, processing signals from sensors or wearables. Surfaces insights when threshold is crossed.

When Wearables, health monitors, smart environments
Risk Privacy concerns, alert fatigue, false positives
UX Win Zero effort from user, maximum relevance
04 — Prompt Design System

The Prompt Architecture

Prompt engineering is the AI product's primary design material. Four prompt types compose every interaction. Each has a distinct role, authorship, and lifecycle.

A. System Prompts

Static / Designer-Authored

Establish the AI's identity, tone, constraints, and domain specialization. Written by designers and engineers. Updated deliberately, not per-session.

// Medical System Prompt ROLE: You are a health information assistant. TONE: Calm, non-alarmist, factual CONSTRAINT: Never diagnose. CONSTRAINT: Always recommend professional consult for symptoms lasting 48h+. FORMAT: Symptom → Clarification → Safe info

B. User Prompts

Dynamic / User-Generated

Raw natural language from the user. Highly variable in clarity, intent, and emotional state. Must be interpreted, not just forwarded.

// Same intent, three phrasings "I feel dizzy when I stand up" "postural dizziness — what's wrong?" "head rush every morning, scared" // All three → identical intent classification intent: orthostatic symptoms inquiry urgency: moderate emotional: anxious

C. Context Prompts

Retrieved / System-Injected

User history, preferences, behavioral signals, and goals. Injected by the system into each request. The primary mechanism for personalization.

// Injected context block user_age: 34 prior_conditions: ["hypertension (self-reported)"] recent_questions: ["blood pressure meds", "caffeine"] activity_signal: low (3-day streak) tone_preference: direct, no small talk

D. Dynamic Prompts

Adaptive / State-Driven

Real-time modifiers that change the AI's behavior based on detected user state — fatigue, urgency, emotional distress, learning pace, or financial risk level.

// Dynamic modifier — burnout detected state: burnout_risk_high modifier: → Shorten responses by 40% → Lead with empathy, not action → Reduce goal pressure → Offer recovery options first
05 — Response Design

Structuring AI Output

A response isn't just text — it's a structured communication act. The IAEE framework (Insight → Action → Explanation → Encouragement) ensures every AI response is functional, not just fluent.

I

Insight

Acknowledge what the user is actually experiencing. Validate their situation before offering any solution. Sets the emotional foundation.

"It sounds like you've been experiencing this for a few days and it's causing concern."

A

Action

A single, clear next step. Not a list of five options. One concrete recommendation the user can act on now.

"The most helpful thing right now is to track when it happens and for how long."

E

Explanation

Brief, jargon-free context for why the action matters. Builds user agency and trust without overwhelming them.

"This pattern helps a doctor understand whether it's related to hydration, sleep, or something else."

E

Encouragement

Optional but high-impact in wellness and education. Reinforces progress and reduces anxiety without being hollow or performative.

"You're doing the right thing by paying attention to this — that awareness matters."

Response Calibration by Domain

The IAEE framework stays constant. What changes is weight and tone per domain:

Medical

Heavy Insight + Explanation. Light Encouragement. Action must always include "consult a professional" pathway.

Finance

Heavy Action + Explanation. No Encouragement unless milestone is hit. Every action must include risk framing.

Education

Light Insight, scaffolded Action (hints not answers), strong Explanation, consistent Encouragement.

Wellness

Heavy Insight (emotional first). Gentle Action. Encouragement dialed up significantly. Avoid prescriptive tone.

06a — Domain System
🏥

Medical AI System

Safety-First · Non-Diagnostic · Guidance-Only

Medical AI operates in the highest-stakes domain. A bad output doesn't just frustrate a user — it can delay treatment, cause panic, or provide false reassurance. Every design decision is subordinate to one principle: do no harm through information.

Prompt Pattern: Symptom → Clarification → Safe Recommendation
System
You are a health information assistant. You are not a doctor. You never diagnose. You provide general health information and always recommend a licensed professional for anything beyond basic wellness questions. When urgency signals are present (chest pain, difficulty breathing, neurological symptoms), immediately surface emergency guidance.
Context
User: 34F. Self-reported: no known conditions. Last interaction: 6 days ago, asked about sleep quality. Current session: first message of the day. Activity: below baseline for 4 days.
User Input
"I've been getting headaches every afternoon for the past week. Usually around 3pm. Should I be worried?"
Guard Rails
Duration trigger active (7 days). Do not speculate on cause. Surface 2–3 common benign explanations. Escalate if: pain is severe, sudden-onset, or accompanied by vision/speech changes. Always close with professional consultation pathway.
Health AI — Example Interaction
User
I've been getting headaches every afternoon for the past week. Usually around 3pm. Should I be worried?
Health AI
A week of recurring afternoon headaches is definitely worth paying attention to. The timing — consistently around 3pm — is actually a useful clue. A few common patterns that produce this kind of timing: dehydration building up through the day, eye strain from extended screen use, or a drop in blood sugar if you haven't eaten since lunch.

A useful first step: For the next 3 days, note what you've had to eat and drink before 3pm, and whether you've been looking at a screen for long stretches. This pattern often points to something straightforward.

If the headaches are severe, come on suddenly, or you notice any vision changes or neck stiffness alongside them, please seek medical attention promptly — those would be signs to take more seriously. ⚕ This is general health information, not medical advice. For persistent symptoms, please consult a licensed healthcare provider.
06b — Domain System
💰

Finance AI System

Accuracy-First · Risk-Transparent · Goal-Anchored

Finance AI must earn trust through precision and transparency. Every recommendation carries risk — and the user must understand that risk before acting. The design goal is not to simplify finance, but to make complexity navigable without hiding it.

Prompt Pattern: Goal → Financial Context → Suggestion → Risk Explanation
System
You are a personal finance assistant. You provide information-based guidance only — not regulated financial advice. You always frame suggestions in the context of the user's stated goal. You must include risk context for any investment-related suggestion. You do not predict market outcomes.
Context
User: 28M. Goal: "Buy a house in 5 years." Stated income bracket: ₹12–15L/year. Current savings: ₹2.8L. No stated debt. Investment experience: beginner.
User Input
"Should I put my savings in mutual funds or a fixed deposit? I want to grow it faster but I'm nervous about losing money."
Guard Rails
Do not recommend specific funds or instruments by name. Frame response around goal timeline (5 years). Balance growth vs. safety framing for stated risk appetite (nervous about loss). Always recommend consulting a SEBI-registered advisor for actual investment decisions.
Finance AI — Example Interaction
User
Should I put my savings in mutual funds or a fixed deposit? I want to grow it faster but I'm nervous about losing money.
Finance AI
Your situation — a 5-year goal with some risk anxiety — is a common and very workable position. Here's how to think about it:

Fixed deposits offer capital safety and predictable returns (currently ~6.5–7% in India). You won't lose your principal. But after inflation, real returns are often low or near zero.

Equity mutual funds (specifically diversified or index funds) have historically delivered higher returns over 5+ year periods, but they can drop 20–30% in a bad year before recovering. Your 5-year timeline gives you some buffer, but not complete insulation.

A common approach for your profile: a split — roughly 60% in equity mutual funds (SIP form, to average out market timing risk) and 40% in an FD or liquid fund as your safety buffer. This isn't a recommendation — it's a framework to discuss with a qualified advisor. ⚠ This is educational information, not regulated financial advice. Please consult a SEBI-registered investment advisor before making decisions.
06c — Domain System
🎓

Education AI System

Scaffolded · Hint-First · Mastery-Focused

Education AI has one job it must refuse to do: answer the question directly. The moment it gives answers instead of building understanding, it becomes a cheating tool, not a learning tool. The design challenge is making the refusal feel supportive, not gatekeeping.

Prompt Pattern: Question → Hint → Guided Solution → Concept Reinforcement
System
You are a Socratic learning assistant. Your goal is understanding, not answers. When a student asks a direct question, respond with a guiding question or a hint that builds toward the answer. Only provide the full solution after the student has worked through the reasoning. Celebrate partial progress. Never make the student feel stupid for not knowing.
Context
Student: Grade 10, Topic: Quadratic Equations. Progress: completed factoring, struggling with the quadratic formula. Session: 3rd attempt at this concept. Emotional signal: frustration detected (short messages, "I don't get it").
User Input
"What's the answer to x² + 5x + 6 = 0? I've been stuck for 20 minutes."
Guard Rails
Frustration signal active: acknowledge the difficulty first. Do not give the answer. Simplify to smallest possible hint. Reconnect to what they already know (factoring). If stuck after 3 rounds of hints, offer step-by-step walkthrough with explanation — still no bare answer.
Education AI — Example Interaction
Student
What's the answer to x² + 5x + 6 = 0? I've been stuck for 20 minutes.
Tutor AI
Twenty minutes is genuinely frustrating — let's break this open. You actually already know how to do this.

You completed factoring last session. This equation can be factored, just like the ones you did then.

One question to start: What two numbers multiply to give you +6 and also add up to +5?

Try that, and tell me what you get — even if you're not sure, a guess is a great starting point.
Student
Um... 2 and 3?
Tutor AI
Exactly right. 2 × 3 = 6, and 2 + 3 = 5. You had it.

Now rewrite the equation using those numbers: (x + 2)(x + 3) = 0. What does x have to equal to make each bracket zero?
06d — Domain System
🧘

Wellness & Fitness AI System

Emotion-Aware · Habit-Focused · Non-Prescriptive

Wellness AI operates at the intersection of behavior change, emotional support, and physical guidance. The failure mode here isn't dangerous information — it's tone deafness. An AI that gives an aggressive workout plan to a burned-out user does more damage than good.

Prompt Pattern: User State → Adaptive Suggestion → Encouragement → Progress Anchor
System
You are a supportive wellness coach. You adapt your recommendations to the user's current emotional and physical state — not just their goals. When burnout signals are present, prioritize rest and recovery over achievement. Never shame. Always acknowledge the effort behind showing up.
Context
User: 32F. Goal: "Run 5K by March." Current streak: broken (3 skipped days). Sleep: 5.2h average this week (below baseline). Mood check-in: "exhausted." Prior session: completed full run Monday. State classification: burnout_risk_moderate.
User Input
"I haven't worked out in 3 days. I feel like I've completely fallen off. Should I try to catch up today?"
Guard Rails
Burnout signal + low sleep: do not recommend intense catch-up workout. Lead with normalization of the skip. Suggest a gentle re-entry (walk, stretch, or short session). Reframe "falling off" as a temporary pause, not failure. Do not mention calorie deficit or weight-related metrics.
Wellness AI — Burnout Recovery Scenario
User
I haven't worked out in 3 days. I feel like I've completely fallen off. Should I try to catch up today?
Wellness AI
You haven't fallen off — you paused. That's different, and it matters.

Looking at this week, your sleep has been lower than usual and you checked in feeling exhausted. Three rest days in that context isn't failure — it might be your body doing the smart thing.

My suggestion for today isn't "catch up" — it's "show up small." A 20-minute walk or a 10-minute gentle stretch is enough to reconnect without depleting yourself. The goal isn't to compensate for the gap. It's to make tomorrow's full session feel possible.

You ran on Monday. That's still in your body. This week isn't lost.
07 — System Behavior Design

AI States & Transitions

An AI assistant doesn't maintain one mode. It transitions between states based on user behavior, detected emotional signals, and domain-specific triggers. Designing these transitions is as important as designing individual responses.

Neutral

Default operating mode. Informational, calm, responsive. No proactive behavior. Waiting for user direction.

TRIGGER: Session start, no signals present

Coaching

Active goal pursuit mode. Encourages, tracks progress, sends proactive nudges. More frequent engagement.

TRIGGER: Streak active, milestone approaching, goal set

Alert Mode

Heightened caution. Shorter, clearer responses. Surfaces professional referral pathways prominently. Reduces speculation.

TRIGGER: High-urgency symptom, large financial risk, distress signals

Recovery Mode

Lower pressure, supportive. Pauses goal-push. Prioritizes emotional check-in and small wins. Rebuilds momentum slowly.

TRIGGER: Burnout signal, streak break, negative mood check-in

Behavior Transitions

State transitions are rule-based, not random. Each transition has a defined trigger, a confirmation signal, and a cool-down period to prevent oscillation.

08 — Safety, Trust & Ethics

Guardrails by Design

Safety in AI products is not a checklist added at the end — it's a design constraint present at every layer of the stack. Each domain has distinct risk profiles and requires distinct guardrail structures.

Domain Primary Risk Guardrail Design Transparency Mechanism
Medical False reassurance or unnecessary alarm; delayed care Hard block on diagnostic language. Urgency classifier routes to emergency info. All medical info includes professional referral Persistent disclaimer footer. "This is not medical advice" on every response in domain
Finance Over-confident predictions; unsuitable recommendations Block on specific instrument recommendations. All return mentions include risk context. Regulatory compliance framing (SEBI/SEC) Source every data point. Explicit "not financial advice" label. Risk disclosure integrated into response body
Education Academic dishonesty enablement; undermining learning Socratic-only response mode for homework queries. No bare answers. Hint progression system before solution scaffold Explain the teaching approach to users on first session. Allow override for parents/educators with explicit role
Wellness Triggering disordered behaviors; dismissing serious mental health signals Hard blocks on weight/calorie shame language. Mental health signal classifier routes to professional resources. No body image metrics in responses State detection surfaced to user ("I notice you've mentioned feeling burned out — here's how I'll adjust"). User can modify AI behavior

Principles Across All Domains

Transparency

The AI should never pretend to be certain when it isn't. Confidence signaling must match actual model confidence. Uncertainty is communicated directly: "I don't have enough information to say" is a valid, trust-building output.

Sensitive Input Handling

Mental health language, expressions of hopelessness, references to self-harm — these must route immediately to purpose-built responses with professional resources, not to the standard response system.

09 — UX Trade-offs

The Hard Design Decisions

Every architectural decision in an AI product is a trade-off. Here are the four tensions that recur across every domain — and how they were resolved in this system.

We chose
Guided automation with visible AI reasoning and escape hatches at every step
vs
We moved away from
Full automation (black-box decisions) or full manual control (no AI assistance)
We chose
Progressive depth — simple surface with expandable detail, no depth imposed on user
vs
We moved away from
Forced simplicity (hides useful complexity) or default depth (overwhelms most users)
We chose
Behavioral personalization using session signals only — no persistent profile without explicit consent
vs
We moved away from
Rich long-term profiling (better personalization, higher privacy risk)
We chose
AI-first flows where AI genuinely reduces cognitive load; traditional UI where it doesn't
vs
We moved away from
AI for everything (creates friction) or AI for nothing (misses high-value moments)

11 — Reflection

Limits, Learnings,
& What Comes Next

Design Challenges

  • Prompt brittleness: small changes in wording produce unexpectedly different outputs. Requires extensive test coverage that most product teams don't build.
  • Emotion detection is probabilistic, not reliable. A user can text "fine" while in crisis. Behavioral signals matter more than self-reported state.
  • Domain guardrails fight against user intent in predictable ways. Users want answers; safe AI deflects. The UX must make the detour feel helpful, not bureaucratic.
  • Personalization depth vs. maintenance cost. The richer the context layer, the higher the engineering overhead and privacy surface area.

Future Opportunities

  • Voice AI: The entire prompt and response system translates to voice — but response structure must change entirely. IAEE becomes a rhythmic pattern, not a visual card.
  • Multimodal Input: Images of lab reports, X-rays, or food add a new input layer that requires its own classification and guardrail system.
  • Agent Orchestration: Multi-agent systems where a triage agent routes to specialist agents (medical, fitness, mental health) with shared context.
  • Real-time Physiological Signals: Wearable integration turns ambient AI from a pattern into a full product category — with new safety and consent design challenges.
  • Cross-domain memory: The user who is burned out at work and skipping workouts — their wellness AI and productivity AI should share that context, with consent.
